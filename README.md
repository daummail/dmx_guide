# DMX 가이드 — Vercel 배포

가이드를 웹에 올리고, **비밀번호를 아는 담당자만 사이트에서 직접 고칠 수 있게** 하는 프로젝트입니다.
고친 내용은 서버에 저장되어 모든 방문자에게 바로 보입니다. 배포는 처음 한 번만 하면 됩니다.

```
_vercel/                 ← Vercel 의 Root Directory 로 지정할 폴더
  index.html             가이드 본체 (편집 기능 + 서버 연동 포함)
  api/login.js           비밀번호 확인 → 편집 세션 발급
  api/content.js         내용 조회(GET) · 저장(POST)
  api/image.js           본문 이미지 업로드
  api/_lib.js            세션·저장소 공통 코드
  vercel.json            정적 파일 위치 설정
```

---

## 배포 순서

GitHub 저장소를 Vercel에 연결합니다. 한 번 연결해두면, 이후 `git push` 할 때마다 자동으로 다시 배포됩니다.

### 1. GitHub 저장소 만들기

[github.com/new](https://github.com/new) 에서

- **Repository name**: `dmx-guide` (아무거나)
- **Private 선택** ← 중요합니다. 내부 문서와 관리자 화면 캡처가 들어 있습니다.
- Add a README / .gitignore 는 **체크하지 마세요** (이미 있습니다)
- **Create repository**

### 2. 올리기

만들어진 저장소 화면에 나오는 주소를 복사해, **`CS 가이드` 폴더**(이 폴더의 상위)에서:

```bash
git remote add origin https://github.com/내계정/dmx-guide.git
git push -u origin main
```

비밀번호를 물으면 GitHub 계정 비밀번호가 아니라 **Personal Access Token** 이 필요합니다.
[github.com/settings/tokens](https://github.com/settings/tokens) → Generate new token (classic) → `repo` 체크 → 생성된 값을 비밀번호 자리에 붙여넣으세요.

### 3. Vercel에 연결

[vercel.com/new](https://vercel.com/new) 에서

1. GitHub 계정 연결 → 방금 만든 저장소 **Import**
2. **Root Directory** 를 `_vercel` 로 지정 ← 꼭 바꿔 주세요 (기본값은 저장소 최상위입니다)
3. 나머지는 그대로 두고 **Deploy**

### 4. 저장소(Blob) 연결

내용과 이미지를 보관할 공간입니다.

1. 프로젝트 → **Storage** 탭 → **Create Database** → **Blob**
2. **공개(Public) 저장소로 만드세요.**
   비공개(Private)로 만들면 캡처 이미지를 브라우저가 못 불러옵니다.
3. 만든 뒤 **Connect** 로 이 프로젝트에 연결
4. 연결 창 아래 **`Add a read-write token env var to this connection` 를 반드시 체크**하세요.
   이걸 빼면 읽기만 되고 저장이 안 됩니다.

연결 후 프로젝트 Settings → Environment Variables 에 `BLOB_READ_WRITE_TOKEN` 이 생겼는지 확인해 주세요.

### 5. 편집 비밀번호 설정

1. 프로젝트 → **Settings** → **Environment Variables**
2. Key `GUIDE_PASSWORD`, Value 에 쓰실 비밀번호
3. Production · Preview · Development 모두 체크 후 저장

### 6. 다시 배포

4·5단계 설정을 반영하려면 한 번 더 배포해야 합니다.
프로젝트 → **Deployments** → 맨 위 항목의 `⋯` → **Redeploy**

### 7. 확인

먼저 주소 뒤에 **`/api/content`** 를 붙여 열어 보세요. 어디가 잘못됐는지 한 번에 알 수 있습니다.

| `/api/content` 결과 | 뜻 | 할 일 |
|---|---|---|
| `{"version":0,...}` 같은 글자 | 정상 | 아래 동작 확인으로 |
| 404 | **Root Directory 가 `_vercel` 이 아님** | Settings → General → Root Directory 를 `_vercel` 로 고치고 Redeploy |
| 500 | Blob 미연결 또는 비밀번호 미설정 | 4·5단계 다시 확인 |

그다음 본 주소에서:

나온 주소를 열고,

1. 오른쪽 아래 **✏️ 편집** → 비밀번호 입력
2. 아무 글자나 고치고 **📤 게시**
3. **시크릿 창**으로 같은 주소를 열어 바뀐 내용이 보이면 성공

시크릿 창으로 보는 것이 중요합니다. 본인 브라우저는 임시저장 때문에 바뀐 것처럼 보일 수 있습니다.

## 문서마다 주소가 있습니다

각 문서는 `https://<사이트>/<문서이름>` 으로 바로 열립니다. 그 주소를 그대로 공유하면 됩니다.

| 문서 | 주소 |
|---|---|
| 문서 홈 | `https://dmx-guide.vercel.app/` |
| 로그인 > 비밀번호 찾기 | `https://dmx-guide.vercel.app/login` |
| 도메인 인증 설정 | `https://dmx-guide.vercel.app/domain` |
| FAQ 중 한 건 | `https://dmx-guide.vercel.app/faq/attachment` |

- 문서 안 소제목까지 가리키려면 뒤에 `#소제목` 이 붙습니다. 주소창을 그대로 복사하세요.
- 예전에 공유한 `#/login` 형태의 주소도 그대로 열립니다 (새 주소로 자동으로 바뀝니다).

## 쓰는 법

| 버튼 | 하는 일 |
|---|---|
| ✏️ 편집 | **편집에 들어갈 때마다 비밀번호를 확인합니다.** 미리보기로 나갔다 다시 들어와도 다시 묻습니다 |
| ✕ 취소 | 편집한 내용을 **버리고** 나갑니다. 고친 게 있으면 한 번 물어봅니다 |
| 📤 게시 | 서버에 저장 → **모든 방문자에게 반영**. 게시가 끝나면 편집 모드에서 자동으로 빠져나옵니다 |
| ⬇️ HTML 다운로드 | 지금 상태를 **혼자 열리는 파일 한 개**로 내려받습니다 (아래 참고) |
| ⋯ | 페이지·카테고리 추가, 임시저장 목록, JSON 백업, 연결 상태 확인 — **편집 모드에서만 보입니다** |

편집 모드에서 나가는 길은 **게시** 또는 **취소** 둘뿐입니다. 고친 것을 게시하지 않고 남겨두려면 `📌 임시저장` 후 취소하세요.

- 고치는 도중 내용은 **브라우저에 임시저장**됩니다. 게시하기 전까지는 나만 보입니다.
- 게시가 실패해도(네트워크·세션 만료·충돌) 고친 내용은 임시저장에 남습니다.
- 두 사람이 동시에 고치면 나중에 게시하는 쪽이 거절됩니다. 새로고침해 최신을 받은 뒤,
  `⋯ → 🗂 임시저장 목록`에서 내 작업을 꺼내 이어서 하면 됩니다.
- 붙여넣은 캡처는 서버에 올라가고 본문에는 주소만 들어갑니다. 문서가 무거워지지 않습니다.
- **첫 게시 때만** 문서에 박혀 있던 캡처를 저장소로 옮깁니다 (진행 창이 뜹니다). 한 번 옮긴 이미지는 다시 올리지 않으니, 이후 게시는 몇 초면 끝납니다.
- 편집 중에는 게시할 때 비밀번호를 다시 묻지 않습니다. 편집을 마치고 나가면 그때부터 다시 필요합니다.
- `⬇️ HTML 다운로드` 는 저장소에 있는 캡처를 **파일 안에 다시 담아** 줍니다 (진행 창이 잠깐 뜹니다).
  내려받은 파일은 인터넷 없이 두 번 눌러 바로 열리고, 그 안에서도 검색·편집이 됩니다.
  다만 서버와는 끊긴 사본이라 `게시` 는 없습니다. 웹에 반영하려면 사이트에서 고쳐 게시하세요.
- `⋯ → 🩺 연결 상태 확인` 으로 저장소·권한 상태를 볼 수 있습니다. 문제가 생기면 여기부터 보세요.
- 「임시저장 목록」에 `문서 교체 전 자동저장` 이 생기는 경우: 새로 배포해 문서가 바뀌었는데, 그 전에 이 브라우저에서 고쳐두고 **게시하지 않은 내용**이 남아 있을 때입니다. 서버 내용과 같으면 만들지 않으니, 이 항목이 보이면 게시 안 된 작업이 있다는 뜻입니다.

## 내용을 크게 바꿀 때

문서 구조를 대폭 손보거나 디자인을 바꿀 때는 원본에서 다시 만듭니다.

```bash
cd ..                                            # CS 가이드 폴더
python3 _source/sync-from-edits.py "게시본.html"   # 편집본 → 원본 반영 (선택)
python3 _source/build.py --vercel                 # _vercel/public/index.html 갱신
git add -A && git commit -m "문서 갱신" && git push   # 밀면 Vercel 이 자동 배포
```

> 서버에 게시된 내용이 있으면, 화면은 **항상 서버 내용을 우선**합니다.
> 파일만 새로 올리고 서버 내용을 그대로 두면 예전 내용이 계속 보입니다.
> 파일과 함께 내용도 갈아 끼우려면, 새로 올린 뒤 편집 모드에서 한 번 **게시**해 주세요.

## 무료 플랜으로 어디까지 되나

무료(Hobby) 플랜의 한 달 한도와, 이 사이트가 실제로 쓰는 양입니다.

| 한도 | 무료 제공 | 이 사이트 |
|---|---|---|
| 저장소 고급 작업 (쓰기·목록) | 2,000회 | **게시할 때만** 씁니다. 페이지를 여는 것으로는 늘지 않습니다 |
| 저장소 단순 작업 (캐시 빗나감) | 10,000회 | 내용 파일 기준 **분당 최대 1회** |
| 저장소 전송량 | 10 GB | 첫 방문당 약 2.3 MB (그림 45장) |
| 사이트 전송량 | 100 GB | 방문당 약 2.2 MB |
| 저장소 용량 | 1 GB | 약 2.4 MB |
| 함수 호출 | 100만회 | 페이지를 열 때마다 1회 |

동시 접속은 걱정하지 않아도 됩니다. 문서 화면은 CDN 이 뿌리므로 사실상 제한이 없고,
서버 쪽은 분당 수백 건까지 여유가 있습니다.

> **게시한 내용은 최대 1분 뒤부터 다른 사람에게 보입니다.**
> 내용 파일을 CDN 이 1분간 품고 있기 때문입니다. 대신 페이지를 열 때마다 저장소를
> 뒤지지 않게 되어, 무료 한도가 5배 이상 늘어납니다.
> 편집 중인 사람은 이 캐시를 건너뛰고 항상 최신을 받습니다.

한도를 넘기면 요금이 붙는 대신 **저장소가 30일간 잠깁니다.** 그동안 문서는 계속 열리지만
(배포 시점 내용) 게시한 수정이 반영되지 않고 편집도 안 됩니다.

> ⚠️ Vercel 약관상 **무료 플랜은 비상업적 개인 용도 전용**입니다.
> 업무로 만들고 관리하는 사내 문서는 원칙적으로 Pro 플랜(월 $20/인) 대상입니다.

## 알아두실 점

- **주소를 아는 사람은 누구나 볼 수 있습니다.** 비밀번호는 *편집*만 막습니다.
  열람까지 막으려면 Vercel 유료 플랜의 Password Protection 이 필요합니다.
- 비밀번호는 코드·저장소 어디에도 들어 있지 않습니다. Vercel 환경변수에만 있습니다.
- 비밀번호를 바꾸면 기존 편집 세션은 모두 끊깁니다.
- 저장되는 내용은 서버에서 스크립트·이벤트 속성을 걷어낸 뒤 보관합니다.
